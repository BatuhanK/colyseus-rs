# 🧠 trivia arena (demo)

LLM-powered multiplayer trivia: 2–4 players + up to 10 spectators per room,
questions generated by DeepSeek per round, global lobby chat, and a leaderboard
fed over a Redis queue.

```
demos/trivia/
  server/   # Rust game backend (colyseus-rs) — port 2568
  web/      # T3 app (Next.js + tRPC + NextAuth + Drizzle/SQLite) — port 3001
  sim.mjs   # headless 2-player E2E simulation (no browser needed)
```

## Run it manually

Prereqs: `redis-server` running locally, `cargo`, `node`.

```sh
# 0) one-time: deps + database
cd demos/trivia/web && npm install && npm run db:push

# 1) game backend (terminal 1)
cargo run -p trivia-server

# 2) web app (terminal 2)
cd demos/trivia/web && npm run dev -- --port 3001
```

Open `http://localhost:3001` in two browsers/profiles, sign up two users,
one creates a game (difficulty + category), the other joins from the room
list, both hit **ready**, the owner (👑) hits **start**.

## Configuration

| env var | where | default | meaning |
| --- | --- | --- | --- |
| `GAME_SECRET` | both | `dev-secret-change-me` | shared HS256 secret for game tokens |
| `REDIS_URL` | both | `redis://127.0.0.1:6379` | results queue `trivia:results` (Redis list) |
| `LLM_API_KEY` | server | (bundled demo key) | DeepSeek API key |
| `LLM_BASE_URL` | server | `https://api.deepseek.com/chat/completions` | OpenAI-compatible endpoint |
| `LLM_MODEL` | server | `deepseek-v4-flash` | model id |
| `ADMIN_TOKEN` | server | `admin123` | admin panel at `http://localhost:2568/admin` |
| `NEXT_PUBLIC_GAME_URL` | web | `http://localhost:2568` | game server URL for browsers |

If the LLM call fails or no key is set, the server falls back to a built-in
question bank so the game always plays.

## Architecture notes (framework features exercised)

- **Command pattern**: all game logic lives in `server/src/commands/`
  (`StartGame → RequestQuestion → QuestionReady → StartRound → EndRound →
  Advance → FinishGame`), dispatched through the room's `Dispatcher`.
- **`RoomSender`**: LLM calls run in background tasks and re-enter the room
  as commands — the actor never blocks on I/O.
- **Anti-cheat**: the correct answer lives only in the room struct (never in
  the synced state) until the reveal phase; choices are shuffled server-side.
- **Prefetching**: round N+1's question is generated while round N plays;
  `phase: "generating"` is what the UI shows while waiting.
- **Rounds**: 20s each, ending early when everyone answered
  (`set_timeout` + `clear_timeout`), 5s reveal break, 10 rounds.
- **Roles**: first 4 lobby joiners are players; latecomers and mid-game
  joiners are spectators. Lobby drops leave immediately (no reconnection
  hold — others can start); mid-game drops get a 60s reconnection window.
- **Session takeover**: rejoining with the same account (new session) moves
  the player entry — score included — to the new session.
- **Global chat**: an `.internal()` room created once at startup via
  `MatchMaker::create_room` (clients can't create it). History lives in
  room-internal state — pushed once on join, then broadcast-only (feeds
  don't belong in state sync).
- **Lobby listing metadata**: rooms publish `{phase, round, players,
  spectators}` so the home page shows live, filterable room cards.
- **Results queue**: finished games are `RPUSH`ed to the Redis list
  `trivia:results`; the web app drains it with `BLPOP`
  (`web/src/server/redis-listener.ts`, started from `instrumentation.ts`) and
  upserts the leaderboard. Results survive web restarts — no PUB/SUB loss.

## Headless E2E test

```sh
redis-server &                       # if not already running
cargo run -p trivia-server &         # game server on :2568
cd demos/trivia && node --experimental-strip-types sim.mjs
# …10 rounds later: winners printed; inspect the queue:
redis-cli LRANGE trivia:results 0 -1   # (if no consumer is running)
```
